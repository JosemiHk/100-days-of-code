# Contribution and completion rules

1. Start from a reproducible problem or a concrete acceptance criterion.
2. Implement a coherent change on a branch. Include meaningful verification.
3. Open a PR explaining the problem, resulting behavior, evidence and limitations.
4. Disclose AI assistance. Credit a coauthor only when that person actually contributed, using their consented identity. An AI tool is not an invented human collaborator.
5. Inspect the diff and checks before merging. Never bypass a required review to pursue a badge.
6. Add a learning entry only after Jose can explain what changed, why and how it was tested. Never add entries for future days.

Independent reviews, stars and accepted discussion answers depend on other people. Do not request them as favors for achievements.

## Definition of done

- Observable behavior or substantive technical documentation changed.
- Relevant commands and results are recorded honestly.
- No credentials, private employer material or personal application data are published.
- Limitations and assistance are stated.
- The change is understandable and reproducible by another developer.

Create issues only for actionable work. Close them when the acceptance criteria are fulfilled, not on a timer. No quota of commits, PRs or issues is required.
