# 100 days of code

Evidence-driven practice by Jose Miguel Perea. The goal is stronger engineering skills and reproducible work. GitHub achievements are a possible side effect, never a completion metric.

## Current state

Repository bootstrap is AI-assisted. **0 learning days are recorded.** Jose has not yet reviewed and explained the bootstrap as a completed learning session. The roadmap is proposed work, not finished experience.

## Run locally

Python 3.12+; no external packages required:

```sh
python -m unittest discover -s tests -v
python tools/progress.py
```

The validator checks dates, day uniqueness, required reflections and existing evidence files. It does not prove understanding, accuracy, originality or authorship; those require human review.

## Work plan

See [the 100-day roadmap](ROADMAP.md), [contribution rules](CONTRIBUTING.md) and [session example](log/EXAMPLE.md).

Use one meaningful branch/PR per coherent change. Record completed work only after running the relevant checks and explaining the result. Work in an existing project can be documented here with a real reference; this initial validator accepts local evidence files only, so include a substantive local case note with the external link.

No empty commits, backdated activity, fabricated coauthors, star exchanges, self-accepted discussion answers or scheduled filler commits. Missed days stay missed. A useful week matters more than seven green squares.
